# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

"Next Train?" — live Irish Rail times as a mobile-first React web app and an Alexa skill, sharing one TypeScript core. The README is detailed and current; read it for product behaviour, API quirks and per-service notes.

## Commands

npm workspaces monorepo (`packages/core|api|web|alexa|infra`). Run from the repo root:

```bash
npm test                                   # vitest, all packages (packages/*/test/**/*.test.ts)
npx vitest run packages/core/test/line.test.ts   # one file
npx vitest run -t "some test name"         # by name
npm run typecheck                          # tsc --noEmit in every workspace
npm run dev:api                            # local API on :3001 (in-memory favourites)
npm run dev:web                            # Vite on :5173, proxies /api → :3001
npm run build:web                          # typecheck + vite build
```

Live-API scripts (hit the real Irish Rail API): `npm run smoke -- connolly south`, `npm run verify-line`, `npm run build-network -w @dart-times/core`, `npm run update-stations -w @dart-times/core`. After `update-stations`, regenerate the Alexa model with `npm run alexa:model`.

Deploy: `npm run deploy` (builds web, then CDK deploy to eu-west-1). Needs AWS credentials — don't run without being asked.

## Architecture

- **No build step for core.** `@dart-times/core` exports its `.ts` sources directly (`exports` → `./src/index.ts`, plus `./dynamo` kept separate so the web bundle doesn't pull in the AWS SDK). Vite, tsx and CDK's esbuild (`NodejsFunction` in `infra/lib/dart-times-stack.ts`) all consume it as source. TS is strict with `noUncheckedIndexedAccess`.
- **Data flow:** browser → `/api/*` (CloudFront in prod, Vite proxy locally) → `api/src/handler.ts` Lambda → `core/src/irishRailClient.ts` → Irish Rail XML API over HTTP (no CORS, HTTPS is broken, so the browser can never call it directly). The Alexa Lambda calls core directly.
- **Lines vs services:** `core/src/line.ts` defines line topology (`DART_LINE`, `ENTERPRISE_LINE`, `CORK_LINE`; Dublin Commuter's four routes are in `core/src/commuter.ts`, paths city end first) and helpers for neighbours, directions and "does this train stop at X". Line helpers default to the DART so Alexa code stays unchanged. `core/src/services.ts` binds a line to its stations and a `matches(raw)` predicate — the API only labels trains "DART" or "Train", so services are identified by origin/destination and train-code patterns. Adding a service means touching `ServiceId`, `SERVICES`, `isServiceId`, the API's `service=` param, station data (`stations.*.data.ts`, Irish names in `stations.ga.ts`) and a `data-service` colour theme in `web/src/styles.css`.
- **Direction is computed, not trusted:** the station page derives each train's direction from the line layout because non-DART API directions read "To Cork" etc.
- **Web navigation** is state in `web/src/App.tsx` (no router). It always opens on the service picker → line map → `TrackView` station page. Dublin Commuter stations open a `StationBoard` grouped by route (`commuterHeading`), and the all-stations `NetworkMap` → `StationBoard`. `?service=&station=` deep links go straight to a station.
- **Maps:** several renderers share one visual style — `LineMap` (hand-drawn DART), `SimpleLineMap`, `SchematicMap`→`PositionedMap` (hand-placed coordinates in `schematics.ts` / `commuterSchematic.ts`), `BranchLineMap` and `TreeMap` (automatic layout via `networkLayout.ts`). `web/src/network.data.ts` is generated by `build-network` (accumulates across runs) — don't hand-edit it.
- **i18n:** UI strings in `web/src/i18n.tsx` (English + Irish). Irish prefixes stay lowercase in capitalised text via the `Caps` component.
- **Favourites:** one DynamoDB table keyed `web:<device id>` / `alexa:<user id>`; web sends `x-device-id`.

## Tests

Unit tests run against XML fixtures recorded from the real API in `packages/core/test/fixtures/` (loaded via `fixtures.ts`); tests should not hit the network.

## Branches

Everything is merged into `main` (the old `feature/network-map`, `feature/cork-commuter` and `feature/dublin-commuter` branches are kept for history). New work goes on a feature branch off `main`. Keep the README's branch table in sync when adding one.
